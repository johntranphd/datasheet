# Worked example: Model Context Protocol, 2025-03-26 revision

Coded against [coding frame v0.1](../frame/coding-frame-v0.1.md). Single coder. No agreement statistic, because there is only one coder. This is a demonstration that the instrument produces checkable codes, not a result.

**Layer:** agent-to-tool.

**Document set coded.** `specification/2025-03-26/server/tools` only. Three dimensions below are marked **incomplete** because they turn on parts of the specification not yet retrieved, and are recorded that way rather than guessed. Coding one part of a multi-part specification and reporting it as the whole document is the error this frame is written to prevent, including when the coder is me.

**Freeze date:** 2 November 2026.

## Dimension 1. Action authorization: P

The specification's Security Considerations state that servers **MUST**:

> Validate all tool inputs
> Implement proper access controls
> Rate limit tool invocations
> Sanitize tool outputs

"Implement proper access controls" is a normative requirement naming the property, so under the frame's decision rule it codes **P** rather than **N**. No mechanism, field, scope object or policy structure is defined, and a conforming implementation is left to decide what proper means.

The only defined denial path is a user interface one. Under User Interaction Model:

> For trust & safety and security, there **SHOULD** always be a human in the loop with the ability to deny tool invocations.

That is a recommendation about where a human sits, not a primitive by which a specific call can be permitted or denied programmatically. It also places the decision above the agent rather than below it.

**Correction to an earlier statement of mine.** I have previously described this interface as defining no action-level permission. The MUST on access controls makes **P** the defensible code. The substance of the observation holds, that nothing is defined, but the stronger phrasing overstates it and a reader who opens the page will find the line in thirty seconds. Recorded here rather than quietly fixed.

## Dimension 2. Command record: P

Under Security Considerations, clients **SHOULD**:

> Log tool usage for audit purposes

A record is named. It is a SHOULD rather than a MUST, it is a client-side responsibility, and no fields, schema, retention or format are defined. **P** under the rule covering a record recommended rather than required and without defined fields.

Note the asymmetry the frame asks coders to watch for: this is a recommendation to log *usage*. Whether that includes calls that were refused, as opposed to calls that executed, is not addressed.

## Dimension 3. Refusal distinguishable from failure: N

This is the dimension on which the document is explicit, and the code is firm.

Under Error Handling:

> Tools use two error reporting mechanisms:
>
> 1. **Protocol Errors**: Standard JSON-RPC errors for issues like: Unknown tools, Invalid arguments, Server errors
> 2. **Tool Execution Errors**: Reported in tool results with `isError: true`: API failures, Invalid input data, Business logic errors

A deliberate refusal on policy grounds is a business logic error. An instrument that has stopped responding is an API failure. Both are enumerated under the same mechanism and both are returned as `isError: true` with a text content block. The specification defines no field, no code space and no convention distinguishing them.

The consequence within the frame's scope: a record built from these returns cannot establish whether a control fired or a machine faulted. The specification offers nothing to record the distinction with, because the distinction is not represented.

## Dimension 4. Revocation in flight: incomplete

The tools document defines no abort or cancel. It recommends a substitute, under client responsibilities:

> Implement timeouts for tool calls

A timeout is not revocation; it changes what the caller waits for, not what the machine does. On that basis the tools document alone would code **N**.

The code is withheld because the specification defines a cancellation notification in its utilities section, which has not been retrieved. The property may be **P** at the whole-specification level, and the expected finding is that cancellation exists with its effect on work already underway unspecified or best-effort, which is exactly the **P** case in the frame. **To verify before this file is cited.**

## Dimension 5. Identity binding: incomplete

The `tools/call` request carries two parameters:

> "params": { "name": "get_weather", "arguments": { "location": "New York" } }

No identity field, and nothing distinguishing an autonomous caller from a human one. The only trust language in the document concerns the provenance of tool metadata:

> For trust & safety and security, clients **MUST** consider tool annotations to be untrusted unless they come from trusted servers.

That is server trust, not command attribution.

The code is withheld because the specification has a separate authorization document, not retrieved. The expected finding is **P**: identity established at the session or credential level, carried by the transport, with no per-command binding and no agent-versus-human distinction. **To verify before this file is cited.**

## Dimension 6. Record integrity and external readability: N

Neither property appears. The only record language is the client-side SHOULD to log tool usage. Nothing defines the record as append-only or tamper-evident, and nothing gives any party other than the operator access to it.

## What this example demonstrates

The frame produces codes a reader can check against the document in minutes, which is the test it needed to pass.

It also produced two things a looser reading did not. It forced a correction to a claim I had previously stated too strongly, because the P rule on normative-but-undefined requirements caught a MUST I had been treating as silence. And it forced three dimensions into an explicit incomplete state rather than letting a single-part reading stand in for a multi-part specification.

Both are arguments for the method rather than against it, and both are reasons the real review needs a second coder.
